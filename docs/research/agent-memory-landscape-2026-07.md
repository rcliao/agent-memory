# Ghost: What To Build Next — Decision Report
**Date:** 2026-07-29 · **Basis:** 7 adversarially-verified candidates + 35 lower-ranked · Two repo facts verified live during writing (see §2.1, §5)

---

## 1. Landscape, honestly

Mid-2026 agent memory is in a credibility recession, not a capability boom. The three independent 2026 benchmarks that actually control their baselines all report the same thing: **extraction-based memory systems lose to keeping the raw transcript.** SocialMemBench scores Graphiti 0.178 / LangMem 0.162 / Mem0 0.143 / cognee 0.120 against 0.345 for uncompressed retrieval and 0.369 for full context — and pairwise bootstrap says no two of those frameworks are statistically distinguishable from each other. GroupMemBench puts the best system at 46.0% with plain BM25 matching or beating most entrants. MemoryAgentBench puts *every* system at 2–6% on multi-hop conflict resolution. Meanwhile the benchmark the whole vendor field cites is broken: 6.4% of LoCoMo's answer key is wrong, its judge accepts 63% of intentionally-wrong answers, plain filesystem operations score 74% on it, and the Zep-vs-Mem0 dispute (84% → 58.44% → 75.14%) never resolved. The one methodologically clean result of the year is negative and structural: **LMEB measures Pearson −0.115 / Spearman −0.130 correlation between MTEB rankings and long-horizon memory retrieval** — the embedding leaderboard ghost has been picking models from is roughly orthogonal, slightly anti-correlated, with the task ghost does.

Where ghost genuinely leads: (a) the write path is **LLM-free and mechanical**, which is the exact stage HaluMem identifies as the field's hallucination source and which Mem0 itself has been quietly retreating toward with its ADD-only ADDITIVE_EXTRACTION_PROMPT; (b) **non-destructive by construction** — soft-delete, bitemporal validity, `contains` edges that keep children, `link_only` reflect default — so ghost is architecturally immune to the context-collapse failure ACE was invented to prevent and to the DELETE-on-contradiction regression Mem0/LangMem ship; (c) **spaced rehearsal on ≥3 distinct access *days*** rather than raw counts, which no published system implements; (d) **eval-first discipline with a frozen clock** — ghost has a lifecycle sim, a parasite bench, a nurture bench, a personal-agent bench, a behavior bench and a HaluMem proxy in-repo, which is more internal instrumentation than any of the surveyed vendors publish. Where ghost genuinely lags: (1) **no polarity signal anywhere** — nothing in the codebase can tell "restatement" from "refutation," which is the root of open problem 1; (2) **no behavior-level eval** — every preference case in `internal/store/eval_personal.go` is a *direct* self-referential query ("what editor do I use"), so oblique/proactive recall is entirely unmeasured; (3) **per-speaker provenance is absent** — the field's best answer here (Subject-Mem, 0.78 attribution vs 0.25–0.46 for everyone else) is a schema change ghost has not made; (4) **multi-hop is weak and the field cannot help** — the SOTA purpose-trained dense retriever gets 59.97 recall on 2Wiki and 60.48 on MuSiQue, so there is no bolt-on to buy.

**Blunt summary: on write-path design and non-destructiveness the field has little to teach ghost — ghost is ahead. On measurement instruments and on polarity, the field has exactly three things worth taking, and they are cheap.**

## 2. Adopt now

Ranked by (measured value) / (effort). All five together are under a week and touch ≤3 packages.

### 2.1 Drop the `utility_count > 0` predicate from low-utility GC — **the purest parasites are exempt from the rule that exists to evict them**
**Mechanism.** `internal/store/sqlite_gc.go:164-171` soft-deletes memories with `access_count >= 5 AND utility_count > 0 AND utility_count/access_count < 0.2`. Verified live this session: the `utility_count > 0` clause means a memory with `access_count = 847, utility_count = 0` — ratio 0.000, the worst possible parasite — is *excluded* from eviction, while one at 0.19 is caught. This is a one-predicate inversion bug, not a design tradeoff.
**Solves.** Open problem 2 (utility parasites), directly and at the root.
**Red eval that must fail first.** Run the existing `internal/store/parasite_bench_test.go` (150 parasites measured live 2026-07-23) and report parasite token share with the predicate present. Then drop it and re-run: token share must fall and the recall canary must not regress. If share doesn't move, the parasite population is dominated by nonzero-utility riders and problem 2 is edge-expansion-shaped, not GC-shaped — which is itself a decisive finding.
**Effort.** ~30 minutes including the bench delta. **Risk.** Low but real: `utility_count = 0` also describes a *newly written* memory that has been injected but not yet credited. Guard with an age floor (created > 14d) or an `access_count >= 20` bump for the zero-utility branch, and keep `sqlNotProtected` (pinned/locked immunity) intact — it already is.

### 2.2 Extend the FAMA lifecycle eval to the `Context()` path and add a restatement arm — **ghost's #1 metric is currently pinned at 1.00 and measures nothing**
**Mechanism.** `internal/store/eval_lifecycle_test.go` already implements Memora's Forgetting-Aware Memory Accuracy (arXiv 2604.20006), but it probes `s.Search(Limit:10)` only. Measured this cycle: `fama_fresh = 1.00` at every epoch in **both** the reflect=true and reflect=false arms; `fama_mrr = 1.00` from day 10. A metric saturated in both arms cannot adjudicate any aggregation change. Add a `Context()`-based arm that asserts the superseded string is *absent* from the assembled block, plus a restatement arm seeded from the already-pinned 0.72–0.75 cosine band in `eval_nurture_embedded_test.go:78-79`, plus a delete/invalidate op class (~20% of Memora's trace, currently unmodeled).
**Solves.** It is the **prerequisite instrument** for any work on open problem 1. Without it, a restatement-aggregation change cannot be scored.
**Red eval that must fail first.** Predicted, and this is the point: the absence assertion will fail immediately via `context.go:563-601`, where a `contradicts` edge (written by `freshness.go:120` on supersede) gets **force-include that bypasses the score cap**. Ghost deliberately injects the superseded fact next to its correction — so under strict FAMA, ghost scores FAA=0 on every superseded fact *by design*. That has never been measured.
**Effort.** ~150 lines, one file, no schema change. **Risk.** The trap is treating an intentional design as a failure and suppressing force-include to make the number go up — that would remove the agent's ability to see a correction beside what it refutes. **Mandatory mitigation: report two labeled channels** — FAA on the `contradicts`-force-included sibling (design, not defect) vs FAA on stale siblings dragged in by `relates_to` expansion (unambiguous defect, and the same population as problem 2).

### 2.3 Add ~6 proactive/oblique preference-recall cases (PrefEval protocol) — **the behavior gap is currently unmeasured on the retrieval side**
**Mechanism.** PrefEval (ICLR 2025 oral, 3,000 pairs, 20 topics) tests whether a preference stated earlier is honored by a query that never names it. Ghost's analogue needs no LLM: seed `prefers tabs, gofmt -s`, then query *"write a shell script that reformats the repo"*; seed `no dairy`, query *"suggest a dinner recipe"*; assert the preference key appears in `Context()` output. Every existing case in `eval_personal.go` names the preference slot in the query, so this surface is untested.
**Solves.** Open problem 3 (behavior gap) — specifically it separates *"retrieval failed"* from *"retrieval succeeded and the agent ignored it,"* which ghost currently cannot distinguish.
**Red eval.** Recall@budget on the 6 oblique cases. **Paired assertion, non-negotiable:** on the same cases, report the count of injected memories with `utility_count = 0`. Otherwise the test is trivially passed by lowering `MinScore`, which directly feeds problem 2.
**Effort.** ~50 lines in `eval_personal.go`, pure Go, offline. **Risk.** If ghost already passes at ≥80%, this closes as a no-op — that is the honest and likely outcome, and it should be run *before* any code changes so it can close cheaply. Do **not** import the PrefEval dataset (English consumer topics, Claude-3-Sonnet judge, ~5% human disagreement); it is not portable and its headline result merely re-confirms ghost's own in-house finding that a Standing-rules section beat flat injection by 25 points (PrefEval's analogue: 7% → 45% with a reminder prompt).

### 2.4 Make the heartbeat LLM tier emit an **operation**, not prose
**Mechanism.** The distillation tier currently returns free text, which ghost must then match to existing memories by cosine — the measured-impossible route. Change the protocol: retrieve the top-5 candidate memories (FTS5 + vector) and pass them to the LLM with their keys; the tier returns `{op: add | reinforce | correct, target_key: <existing key or null>, content: ...}`. Ghost validates the key exists and applies the op deterministically. **Ask the model only "same slot? yes/no" — never "which is current?"** Freshness stays `max(version)` in Go (the one genuinely transferable rule from arXiv 2606.01435, whose own no-signal regime measured *negative*: 57.8% deterministic vs 64.4% LLM on LongMemEval knowledge-update).
**Solves.** Open problem 1, on the LLM-tier half, by making REINFORCE **identity-based instead of similarity-based** — which sidesteps the cosine ordering inversion entirely rather than trying to beat it.
**Red eval that must fail first.** Seed N heartbeat restatements of one rule. Assert current behavior: N memories with 1 rehearsal day each, none reaching the ≥3-distinct-days promotion gate, and ≥2 co-occurring in one packed context. Then assert post-change: **1 memory with N rehearsal days.** Also hand-label K rule-clusters from the real heartbeat corpus first — if sibling count per rule isn't already ≥3 on real data, problem 1 is smaller than believed and this should not ship.
**Effort.** Small–medium; prompt + a write-path validator. Off the hot path. **Risk.** The LLM emits a wrong `target_key` and reinforces the wrong memory. Mitigate by rejecting any target whose cosine to the new content is below ~0.5 (a *floor*, not a decider) and by never letting `reinforce` overwrite content — only bump rehearsal/access. Note this does **not** fix the mechanical capture tier, which has no LLM; that half needs §5.

### 2.5 One-day conditional-conflict fixture against the supersede path
**Mechanism.** `freshness.go`'s `changeCueRe` fires on `switched to / now uses / instead of / 改成 / 換成`, and `detectSupersede` then demotes the older memory (0.5× importance + `contradicts` edge + forced rank reorder) once entity or distinctive-token overlap passes — with **no conditionality check anywhere in `internal/store/`**. A context-dependent preference — *"I drink coffee in the morning"* then *"I switched to milk at night"* — trips both the cue and the overlap, and ghost demotes a still-valid alternative. Context-qualified preferences are among the most common shapes in personal-agent memory.
**Solves.** An unlisted problem: silent demotion of coexisting facts. Adjacent to #1 and #2 as ranking hygiene.
**Red eval.** Hand-write ~8 fixtures: 4 conditional (morning/night, work/home, prod/dev, zh-TW pair using 改成/其實不是 — the English-only benchmark literature would never exercise ghost's CJK cues) and 4 true dynamic conflicts as controls. Assert the conditional pairs are *not* demoted. **Do not import the MemConflict corpus** — different extraction pipeline means the published table's numbers are uninterpretable for ghost.
**Effort.** One day. **Risk.** The obvious fix (suppress supersede when the pair carries disjoint context qualifiers) is a regex-and-overlap heuristic layered on a regex-and-overlap heuristic — the exact brittleness class that produced the write-time-cosine NO-GO. Also, freshness detection already bought a measured win (personal-agent meanMRR 0.745 → 0.790; FAMA fresh-wins 0.67 → 0.33 without the guard). **Any conditional guard must be re-run against the personal-agent and lifecycle evals before merge.** And scope must stop at *"do not silently demote"* — never *"pick the true one,"* which has no LLM-free solution and would quietly become a request for a cloud LLM on the write path.

## 3. Trial / assess

### 3.1 NLI polarity gate at reflect time — **the only instrument that could beat the cosine inversion** (assess, 1 hour to decide)
Ghost has *measured* that restatements sit at cosine 0.72–0.75 while a correction-vs-the-stale-fact-it-refutes sits at 0.83 and a same-template-different-day pair sits at 0.98. **The must-merge zone is below the must-not-merge zone.** No scalar threshold can work; a 3-way entail/neutral/contradict head is a different axis and the only proposed mechanism on a different axis.
**Cheapest deciding experiment — no ghost code at all, ~1 hour.** Export `cross-encoder/nli-deberta-v3-xsmall` (~22M, SNLI-test 91.64, MNLI-mm 87.77, ONNX exists via the Xenova family) and run it over the *exact* pairs already pinned in `internal/store/eval_nurture_embedded_test.go`: the 3 restatements (0.72–0.75, must merge), the correction/stale pair (0.83, must not), the 0.98 same-template pair.
**GO gate:** bidirectional entailment on all 3 restatements AND contradiction — or at minimum *not*-bidirectional-entailment — on the correction pair, holding in both English and zh-TW phrasing. Then widen to ~30 real pairs mined from the live DB at cosine 0.60–0.90 and require **precision ≥ 0.9 on the merge decision** (a wrong merge destroys a correction).
**Two defects in the naive version that must be fixed before any Go is written.** (a) **Candidate-gate mismatch:** verified live, `edgeAutoLinkThreshold()` returns **0.85**, not the 0.80 the proposals assume — so the existing candidate shortlist contains *zero* of the 0.72–0.75 pairs the model exists to fix, while containing the 0.83 correction it must not merge. The NLI candidate gate must drop to ~0.65, which multiplies pair volume and makes false-positive rate the binding constraint (cap with `MaxPairs`, as `edge_infer.go` already does). (b) **hugot 0.6.4 cannot emit 3-class pair logits today** — `CrossEncoderPipeline` returns one float32 per document and `TextClassificationPipeline` doesn't accept pairs. Route via `ZeroShotClassificationPipeline` or a thin custom pipeline over the shared session in `ort_shared.go`. **Prototype that plumbing first: it is the difference between medium and large effort.**
**Known transfer risk (do not hand-wave it).** XNLI/MNLI accuracy is on well-formed declaratives. Ghost's restatements are prohibitive imperatives ("Avoid inventing non-standard idiom phrasing…" / "Do not use invented or non-standard idioms…"). Published cross-task collapse for MNLI models is severe (90.2 in-domain → 31.4/29.5/55.6 F1 cross-task), and NLI models lean on lexical-overlap and subsequence heuristics — the same shortcut that fires on near-duplicate rules *and* on a correction that restates most of the fact it refutes. This is precisely why the 1-hour probe runs before anything else.

### 3.2 Ettin cross-encoder reranker swap — **measured +0.049 NDCG@10 over ghost's exact current model, at 2× throughput and fewer params**
`ettin-reranker-17m` scores 0.5576 on MTEB(eng,v2) Retrieval mean NDCG@10 reranking identical candidate lists; **ghost's current `ms-marco-MiniLM-L-6-v2` (22.7M) scores 0.5082**. 17M params, 7517 pairs/s vs 3817 (H100, bf16+FA2), Apache-2.0, plain pointwise cross-encoder head so it drops into ghost's MaxP path with a model-path change. The 68m variant is 0.5915 and the sub-100M band is the compute-efficient sweet spot per arXiv 2603.04816 ("68M outperforms 400M at equal compute").
**Cheapest deciding experiment:** swap the model path, run `latency_bench_test.go` + the personal-agent and MAB evals. Gate on both meanMRR and p95 latency inside the 200–900ms budget. **Caveat: throughput numbers are H100, not CPU — measure ONNX CPU latency yourself.** Ettin is English-only, so the cross-script skip in `crossscript.go` stays exactly as-is; this does not fix the CJK gap and must not be sold as doing so.

### 3.3 Query-aware gating on spreading activation — the LLM-free attack on parasites riding edge expansion
Gate every propagation step by the node's cosine to the **query**, not to the seed: `Δr(v) = α·σ(v)·Σ_neighbours r(u)` with `σ(v) = max(cos(e_v, e_q), 0)`, α=0.7, τ=0.01, fixed depth T=3, plus a monotonicity constraint (u contributes to v only if `r(u) > r(v)`). Measured +4.78 F1 over naive vector retrieval on MuSiQue and **+3.35 F1 / +5.25 EM over HippoRAG**, i.e. it beat a PPR baseline on the same harness — relevant because ghost measured PPR itself as a NO-GO. The authors report the query gate alone suppresses hubs without needing degree normalization.
**Why it matters here:** ghost has 18.7k of 39.4k edges saturated at max weight. Spreading activation over a saturated graph is nearly uniform diffusion; a query gate is the cheapest way to restore selectivity without touching the Hebbian rule. **Cheapest experiment:** implement the gate behind a flag in `context.go` Phase 3, re-run the parasite bench (parasite token share) and the hop2 eval (multi-hop, currently measured no-lift). Two metrics, one flag. Also touches open problem 4.

### 3.4 TM2C2 convex fusion as an alternative to RRF — small, and it protects `MinScore`
`score = a·norm(dense) + (1−a)·norm(bm25)`, normalized by **theoretical** min/max rather than empirical per-query min/max. Peer-reviewed (Bruch et al., ACM TOIS 2023): RRF is sensitive to its `k`; convex combination outperforms it in- and out-of-domain; `a` is tunable from a few dozen labeled queries. The ghost-specific argument is sharper than the paper's: empirical min-max forces the top result to 1.0 on every query, which **destroys the cross-query absolute-confidence signal ghost's `MinScore` floor depends on.** Cheapest experiment: implement behind a flag, sweep `a` over the existing personal-agent eval, compare meanMRR *and* the variance of top-1 fused score across queries.

### 3.5 The embedding-migration decision needs a ghost-native bench, not MTEB
Ghost is mid-migration to `paraphrase-multilingual-MiniLM-L12-v2` on the strength of a cross-lingual fix (1/20 → 20/20) — good, that was measured on ghost's own task. But LMEB's −0.115/−0.130 MTEB correlation means any *further* model choice made from a leaderboard is a coin flip. Two concrete alternatives worth benching, both 384d and therefore **schema-compatible with the existing embedding column**: `granite-embedding-97m-multilingual-r2` (97M, 384d, MTEB-v2 Multilingual Retrieval 60.3 vs multilingual-e5-small's 50.9, ships ONNX + int8 OpenVINO, no instruction prefixes required, Apache-2.0). Gate on ghost's own crosslingual + personal-agent evals plus CPU latency, never on the leaderboard number. **Also note LMEB's instruction-prefix finding: bge-m3 *drops* 6 points with instructions while mE5-large-instruct *gains* 5 — prefixing is model-specific and can hurt badly.**

### 3.6 Subject-Mem indexing for open problem 5 (provenance) — the only measured answer in the literature
Extraction emits `(speaker, subject, fact)`; the row is indexed by **subject**, with speaker retained as provenance metadata. Measured on SocialMemBench: attribution accuracy 0.78 vs 0.25–0.46 for Graphiti/LangMem/Mem0/cognee, against a 0.82 ceiling set by raw-turn retrieval. The three pathologies it names map directly onto ghost: statements A makes *about* B get filed under A; group consensus overwrites individual dissent; preferences version by recency instead of by who-held-what-when — meaning ghost's supersede must be scoped per-holder, i.e. the version chain keys on `(subject, slot, holder)`, not `(slot)`. **This is a schema change and therefore needs explicit human approval per CONVENTIONS.md — do not start it as a side effect of anything above.** Cheapest pre-work with zero schema cost: write ~6 group-chat attribution fixtures against the current store and measure how badly ghost actually fails. If ghost is near 0.25 like the field, the schema conversation is warranted; if tag conventions already carry the speaker adequately, it isn't.

### 3.7 MemDelta's matched-budget controls — a methodology upgrade, ~free
Before accepting any retrieval win from §3.2–3.5, run four trivial controls at **identical injected-token budget**: recency-only (last-N), frequency-only (most-accessed), long-context, and random. MemDelta's measured claim is that gaps >30 points sometimes *disappear or reverse* under matched budgets, and that systems with identical aggregate scores disagree on 16–66% of individual items. Ghost already pre-registers via a frozen clock; adding matched-budget controls and per-item disagreement to the eval harness makes every future number in this repo stronger for roughly a day of work.

## 5. Restatement aggregation: a concrete design

**The constraint, restated precisely.** Ghost has measured a *cosine ordering inversion*:

| pair type | cosine | required action |
|---|---|---|
| LLM restatements of one rule | **0.72 – 0.75** | **merge** |
| correction vs the stale fact it refutes | **0.83** | **must not merge** (supersede) |
| same template, different day | 0.98 | merge |
| ghost's auto-link gate (verified live, `edge.go:159`) | **0.85** | — |

Two consequences most proposals miss. First, no scalar threshold can separate rows 1 and 2 — that is a proof, not an opinion. Second, **the current 0.85 candidate gate never even sees the pairs that matter**: the restatement band sits 0.10–0.13 *below* it, while the correction pair sits below it too. Any polarity model bolted onto the existing candidate stream would be adjudicating an empty set.

### The design: three layers, each independently gated, none destructive

**Layer 0 — instrument (blocking prerequisite).** §2.2. Without a non-saturated FAMA restatement arm there is no way to score layers 1–2. Do this first, always.

**Layer 1 — eliminate the matching problem for the LLM tier (§2.4).** The heartbeat tier already has a model in the loop, off the hot path. Give it the candidate keys and have it return `{op, target_key}`. Restatement aggregation on the LLM tier then becomes **identity-based**, and the cosine inversion is irrelevant to it. This is the highest-value, lowest-risk piece and it needs no new model, no new dependency, no schema change. **Expect this to cover the majority of the sibling explosion**, since problem 1 is stated as an *LLM-tier* pathology ("the LLM tier rewrites the same lesson in fresh words each heartbeat").

**Layer 2 — polarity for the mechanical tier and for legacy siblings (gated on the §3.1 probe).** The mechanical capture tier has no LLM and the existing DB already contains sibling clusters, so Layer 1 cannot reach them. Design:

1. **Candidate generation:** lower the gate to **~0.65** cosine (below the 0.72 restatement floor, with headroom), scoped to the same namespace, with a hard `MaxPairs` cap per reflect run mirroring `edge_infer.ListReasoningCandidates`. Skip cross-script pairs via the existing `crossscript.go` logic — the English-only models must never see them.
2. **Decision:** **Bidirectional Entailment Clustering** (Farquhar et al., *Nature* 630, 2024 — peer-reviewed, code released, and the clustering step is *ablated*: unidirectional entailment and embedding similarity both degrade it). Greedy single pass; for a new memory `x` and each cluster representative `r`, run the NLI head **twice** — `NLI(premise=r, hyp=x)` and `NLI(premise=x, hyp=r)`. Assign to the cluster **iff both directions return entailment**. Critically, BEC prefixes both sides with shared context (`"{context} {answer}"`); **ghost's analogue is prefixing the rule's topic/entity slug**, and this conditioning is load-bearing — skipping it is a common reason BEC underperforms.
3. **Outcome mapping (non-destructive only):** bidirectional entailment → reinforce one canonical memory, rehearsal days union'd, siblings archived to dormant under a `contains` edge (the path `applyDedup` already implements); one-way entailment → `refines` edge, **never a merge** (the source paper's rule of dropping the specific fact and keeping the general one is **actively wrong for personal memory** — "prefers dark mode in Ghostty" is the useful one); contradiction → `contradicts` / supersede candidate, which mostly duplicates what `write_triage.go` already does cheaply, so treat it as a cross-check not a replacement.

**Known unknown, stated plainly:** none of these were trained or evaluated on imperative agent rules, and MNLI models are documented to over-predict `neutral` on short imperatives. The realistic failure mode is not a wrong merge — it is a **no-op**: two rewrites of one standing rule scoring `neutral`/`neutral` and never clustering. **That is exactly what the 1-hour, 5-pair probe in §3.1 falsifies, and it is why no Go gets written first.**

**Layer 3 — rendering, which is orthogonal and must not be blocked.** Ghost already measured that a dedicated "Standing rules" section beat flat injection by **25 points**, and PrefEval independently measured 7% → 45% from a reminder prompt — *identical information, different rendering, 6× accuracy.* One caution circulating is that PrefEval's repetition finding conflicts with aggregation; **it does not.** PrefEval's repetition is *in-prompt restatement across dialogue turns*, not *duplicate stored records*. Ghost can aggregate three siblings into one canonical memory and still render it prominently and repeatedly. Prove it rather than assume it, with a rendering-only A/B that holds retrieval output fixed: (a) three sibling restatements, flat; (b) one aggregated rule, flat; (c) one aggregated rule in the Standing-rules section. **If (c) ≥ (a), aggregation is unblocked** and layers 1–2 proceed unchanged.

**Sequence:** Layer 0 → Layer 1 → 1-hour probe → (Layer 2 only if green) → Layer 3 A/B in parallel throughout.

## 6. What ghost knows that the field does not

Six things in this repo are genuinely novel and publishable. The first is the strongest.

1. **The cosine ordering inversion.** Restatements at 0.72–0.75, correction-vs-refuted-fact at 0.83, same-template-different-day at 0.98 — **the must-merge zone sits below the must-not-merge zone.** Every LLM-free dedup design in the field (Graphiti's 0.6 candidate floor, SimpleMem's 0.85 cluster threshold, A-MEM's top-k, Memobase's slot merge) implicitly assumes the opposite ordering. Nobody publishes this measurement. It is a clean, reproducible negative result with a one-figure presentation and immediate design consequences for a dozen systems. **Write this one up first.**

2. **Hebbian saturation is a measured pathology, not a theoretical worry.** 18.7k of 39.4k edges pinned at max weight. Co-retrieval strengthening is proposed constantly (MemoryBank's `S += 1` on recall is the identical loop) and nobody reports the saturation endpoint or the parasitic consequence: memories with 1000+ injections and <1% utility riding in via edge expansion on a graph that has lost its selectivity.

3. **Rendering beats retrieval, measured on an LLM-free store.** The 25-point Standing-rules result is stronger evidence than PrefEval's because ghost's retrieval was held fixed and no judge model was involved. The field's entire optimization pressure is on retrieval quality; ghost has evidence the packing format is comparably load-bearing.

4. **Deliberate `contradicts` force-include — a defensible position against the field's consensus.** Ghost injects the superseded fact *next to* its correction, bypassing the score cap (`context.go:563-601`). Under a strict FAMA forgetting-absence criterion, ghost scores FAA=0 on every superseded fact **by design**. Mem0/LangMem delete on contradiction; MemSyco-Bench measured A-Mem at **24% accuracy despite retrieving both the old and updated memory** — retrieval succeeded, disambiguation failed. Ghost's bet is that showing the pair is better than silently picking a winner. That bet is testable (§2.2) and, either way, is a paper.

5. **Spaced rehearsal on distinct *days*.** Promotion requires ≥3 distinct access days, not raw access count. This is the direct antidote to the utility-parasite / recency-contamination class, and no surveyed system implements it — every one of them counts events, which is trivially gamed by a single busy session.

6. **A mechanical, LLM-free write path that survives the benchmarks that kill LLM extraction.** HaluMem's finding is that LLM extraction and update *generate and accumulate* hallucinations that propagate to QA; SocialMemBench's is that every extraction-based system scores roughly *half* of keeping the raw transcript. Ghost's regex-intent-cue + rule-based-NER + CJK capture tier, plus REINFORCE/CORRECT triage that inherits importance from the superseded fact, is a design nobody in the field is defending — and Mem0's quiet retreat to an ADD-only additive prompt is independent corroboration from an implementer with every incentive to say otherwise. The zh-TW/English cross-script findings (1/20 → 20/20 on the embedder swap; the measured necessity of skipping the English-only reranker on cross-script windows) are a second contribution here — the field is essentially monolingual and does not report these failure modes at all.
